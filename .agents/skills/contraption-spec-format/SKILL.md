# contraption-spec-format

The schema for `ContraptionSpec` JSON — the durable artifact that
drives every build — and the HTTP transport that carries it.

> Status: transport contract complete (Phase 2). Spec schema lands in
> Phase 3.

## Transport contract (Phase 2)

The pack does **not** serve HTTP directly — `@minecraft/server-net`
is outbound-only. We use a Node daemon (`tools/forge.mjs`) as the HTTP
broker:

```
agent / CLI  --HTTP-->  forge daemon  <--HTTP-- pack (outbound)
```

### Authentication

Every request to the daemon (from either the agent or the pack)
must include:

```
X-Forge-Token: <token>
```

The token is a 256-bit random hex string, generated by
`tools/pack-deploy.ps1` on first deploy and shared between:

- Host side: `.env` at the repo root (`FORGE_TOKEN=…`).
- Pack side: `<bds>/config/<pack-uuid>/secrets.json` →
  `{ "forge_token": "…" }` → loaded as a `SecretString` by
  `@minecraft/server-admin`.

No `Bearer` prefix — the token is the raw header value. This avoids
string-concatenating a `SecretString` (which would expose it to the
script context).

Wrong / missing token → `401 unauthorized`.

### Endpoints (Phase 2 surface)

| Method | Path         | Caller | Body                                  | Response                                                                               |
| ------ | ------------ | ------ | ------------------------------------- | -------------------------------------------------------------------------------------- |
| POST   | `/heartbeat` | pack   | `{ timestamp, packVersion, anchor }`  | `{ ok: true }`                                                                          |
| GET    | `/health`    | agent  | (none)                                | `{ ok, anchor, packVersion, lastHeartbeat, heartbeatCount, daemonStartedAt }`           |
| GET    | `/anchor`    | agent  | (none)                                | `Anchor \| null`                                                                         |
| POST   | `/echo`      | agent  | any string                            | `{ echo: <body> }`                                                                      |

Heartbeat cadence: every 40 ticks (≈2s). The daemon caches the latest
heartbeat; agent queries serve from that cache. So state visible to
the agent lags the world by ≤2 seconds.

### Anchor shape

```ts
type Anchor = {
  dimension: string;                              // "minecraft:overworld"
  pos: { x: number; y: number; z: number };       // integer block coords
  facing: "north" | "south" | "east" | "west";    // derived from yaw
  setBy: { name: string; id: string };
  setAt: number;                                  // ms since epoch
};
```

### Failure modes

- Daemon down: pack heartbeats fail; pack logs the first
  `QUIET_AFTER_N_FAILURES` failures then suppresses. CLI commands
  return `connection failed` and exit non-zero.
- Token mismatch: daemon returns 401, pack logs the response body once
  per failure window. Re-run `tools/pack-deploy.ps1` to regenerate
  consistent secrets on both sides.
- Pack not yet heartbeated: `forge health` returns
  `lastHeartbeat: null, heartbeatCount: 0`.
